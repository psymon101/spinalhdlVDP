ITEM 1 — HDMI reset sequencing (cold-start reliability)     RESULT: no flakiness
------------------------------------------------------------------------------
Concern (CyanPeak F4): pixelReset may not be gated on PLL/clkdiv lock, risking a
cold-start HDMI bring-up race. Recommended fix IF flakiness observed:
  pixelReset = !clkdiv.RESETN
Decision rule (PM #14424, measure-first): apply the gating ONLY if cold-start
flakiness is observed.

Observation run (PM-authorized #14424):
- Bitstream: fpga/tang20k/impl/pnr/project_a5a047a2_bankcompletion.fs
  sha256 a5a047a23d98293d077f2b0bdc322f375545677ffa53d0722a91be9cf327658c
- Method: N=10 POR cold-starts via `openFPGALoader -b tangnano20k <fs>` (clean
  config + PLL re-lock). Per cycle: reconfigure -> 5 s settle -> capture one
  /dev/video0 frame -> mean YUV + sha. HDMI-lock inferred from frame-content
  consistency (this UVC capture device does not support --query-dv-timings).
- Baseline (pre-run, content present): checkerboard, YAVG=125.3, neutral chroma
  (HDMI locked). Post-reconfigure frames drop to YAVG=16.13 (empty-SDRAM
  backdrop) — this baseline->backdrop transition proves the capture is LIVE and
  each reconfigure took effect.

Result: 10/10 cycles reconfig_exit=0 AND capture_exit=0, and every cycle produced
a BYTE-IDENTICAL valid HDMI-locked frame:
  YAVG=16.1325  UAVG=128.029  VAVG=127.914  sha 12038428e646... (1 unique hash / 10)
Zero no-sync / blank / garbled / outlier events.

Verdict: OUTCOME A — cold-start bring-up reliable; NO RTL change (pixelReset
gating NOT applied).

Limitations (disclosed): (1) This is a JTAG POR-reconfigure proxy, NOT a true
power-on cold-start — no operator power-cycles were available, so the power-ramp /
reset-release timing that a genuine reset-sequencing race would exploit is not
exercised. The result is a positive signal but does not fully clear the power-on
case; a definitive close would want an operator-run N=10 power-on series.
(2) HDMI-lock inferred from frame-content consistency, not DV-timings (device
limitation). PM may accept this proxy close or schedule the stronger power-on run.
